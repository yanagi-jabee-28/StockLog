# StockLog (ストックログ) 📦

**StockLog** は、日々の備品や食材の管理を「もっと楽に、直感的に」することを目指した、個人向けの在庫管理アプリケーションです。

公開サイト: https://yanagi-jabee-28.github.io/StockLog/

GitHub: https://github.com/yanagi-jabee-28/StockLog

## 🌟 特徴

- **オフライン・プライバシー重視**: 
  全てのデータはブラウザの `localStorage` に保存されます。外部サーバーを介さないため、プライバシーが守られ、高速に動作します。
- **モバイルファースト設計 (Vibrant UI)**: 
  スマートフォンの片手操作、特に「親指」での使いやすさを徹底追求。鮮やかなカラーパレットで、毎日の管理が楽しくなります。
- **プロフェッショナルなPC表示 (Master-Detail)**: 
  大画面ではサイドバー付きのダッシュボード形式に切り替わり、大量のアイテムも効率的に管理できます。
- **開封済み管理機能**: 
  単なる在庫数だけでなく、開封した個体の「残存量（%、またはグラム数など）」を個別に管理できる「気の利いた」ロジックを搭載。
- **カテゴリの実用再設計**:
  「食・住・衣・己」の考え方でカテゴリを整理し、衣類カテゴリ（ワードローブ / インナー / 服飾雑貨 / 季節もの）を追加。
- **価格情報の単位正規化**:
  内容量単位を自由記述ではなく選択式（個数・重量・容量）で入力。単価比較の表記ゆれを抑制。
- **開封フローの個体分離**:
  「1つ開封」で在庫から1個だけを使用中アイテムとして分離。未開封在庫と開封中を同時管理可能。
- **安心のデータポータビリティ**: 
  JSON形式でのエクスポート・インポートに対応。バックアップや機種変更時のデータ移行も簡単です。

## 🚀 使い方

1. **アイテムの追加**: 
   右下の「＋」ボタン（PCは右上のボタン）から名前、カテゴリ、単位を選んで登録。
2. **在庫調整**: 
  未開封在庫セクションでロットごとに「-1 / +1」で調整。
3. **開封**: 
  未開封在庫のロット行から「1つ開封」。使用中セクションに個体が分離され、個別の残量管理が始まります。
4. **アラート**: 
   在庫が設定した基準値を下回ると赤く表示され、買い忘れを防ぎます。
5. **同名ロット管理**:
  同じ商品名の在庫はアコーディオンで束ねて表示。内容量・期限が異なるロットを見分けながら開封順を決められます。

## 🧪 ローカル検証とPages差分の注意点

- **データ保存先が別になる**:
  本アプリは `localStorage` を使うため、`http://localhost:3000`（または3001）と `https://yanagi-jabee-28.github.io/StockLog/` は別オリジンとして扱われます。片方で登録した在庫は、もう片方には自動共有されません。
- **`npm run dev` と Pages は実行モードが違う**:
  開発確認は `npm run dev`、Pagesに近い確認は `npm run build && npm run preview` を推奨します。
- **ポート競合時の挙動**:
  3000番ポートが使用中の場合、Viteは自動で3001などに切り替えます。URLを見て接続先を確認してください。
- **古いアセットが見える場合**:
  ブラウザキャッシュの影響で更新が反映されないことがあります。スーパーリロード（ハードリロード）で再確認してください。

## 🗂️ カテゴリ体系

- 🥬 冷蔵保存（生鮮・要冷蔵品） / 🧊 冷凍保存 / 🧂 調味料（常温） / 🍘 乾物・保存食 / 🥤 飲料・嗜好品
- 🧻 日用消耗品 / 💄 コスメ・美容ケア / 🩺 医療・ヘルスケア
- 👕 衣類・ワードローブ / 🧦 インナー・靴下 / 👟 靴・服飾雑貨 / 🧥 季節もの・保管衣類
- 🔧 住設・家電消耗品 / 🎨 趣味・探求 / 🪑 家具・インテリア / 🧰 防災・備蓄

旧バージョンのカテゴリIDは読み込み時に自動で新IDへ移行されます。

## 🔒 データ整合性ルール

- 未開封ロットが在庫の正本です。
- 開封中アイテムはロットから派生する個体で、`stock = 1` を維持します。
- 親ロットを削除すると、紐付く開封中アイテムも連鎖削除されます。
- 親ロットが存在しない開封中データ（孤児データ）は、読み込み/インポート時に自動削除され履歴に記録されます。
